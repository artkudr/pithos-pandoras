# Rust: базовые правила

Действуют всегда. Подробности — в скиллах `rust-core`, `rust-arch`, `rust-data`,
`rust-web`, `rust-testing`.

## Ошибки

- Домен и сервисы — `thiserror` и типизированные ошибки. `anyhow` — только в
  `main`, CLI и на границе запуска.
- `unwrap`, `expect`, `panic!` запрещены вне тестов и старта приложения.
  Пользовательский ввод всегда возвращает ошибку, а не панику.
- Ошибка приложения — enum с полями `code`, `message`, `hint`, `allowed`.
  Она сериализуется в JSON и не теряет допустимые значения.
- `?` вместо `match`, если не нужно добавлять контекст. Контекст — через
  `map_err` или `thiserror`.

## Async

- `tokio`, multi-thread runtime.
- `rusqlite` синхронный. Не вызывать его в async-задаче напрямую: только через
  `spawn_blocking` или отдельный writer-поток.
- Не держать `Connection` и `Transaction` через `.await`.
- Транзакции короткие. Сетевых вызовов и долгих вычислений внутри нет.

## Владение

- Вход — `&str`, `&[T]`, `&Path`; хранение — `String`, `Vec<T>`, `PathBuf`.
- `Clone` только осознанно. Для разделяемого состояния — `Arc`.
- `newtype` для `ProjectName`, `RoleName`, `TaskId`: строки не должны
  путаться между собой.
- `unsafe` запрещён без отдельного решения и записи в `docs/`.

## Стиль

- `snake_case` — функции и модули, `PascalCase` — типы, `SCREAMING_SNAKE_CASE` —
  константы.
- Функция — глагол: `create_task`, `start_stage`. Для fallible — `try_`; для
  bool — `is_` / `has_`.
- Публичные элементы — с `///`, модули — с `//!`. Комментарий объясняет «почему»,
  а не пересказывает код.
- `#[allow(...)]` — только с причиной в комментарии.
- Форматирование — `cargo fmt`, линты — `cargo clippy -- -D warnings`.

## Зависимости

- Новая зависимость — только с обоснованием: что даёт и почему без неё нельзя.
- `Cargo.lock` фиксируется. `cargo deny check` — перед крупной сдачей.
- Не тянуть тяжёлый крейт ради одной функции.
