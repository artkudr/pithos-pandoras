# Домен PithosPandoras

Источник правды — `docs/Сервис-задач-архитектура.md`. Здесь — рабочая выжимка
для кода.

## Сущности

- **Проект** — набор задач, ролей и статусов. Имя берётся из `AGENTS.md`.
- **Роль** — зарегистрированное имя агента. Не появляется при первом упоминании.
- **Задача** — номер внутри проекта, название, постановка, статус, маршрут.
- **Этап** — работа одной роли; у этапа есть круг. Отдельного имени у этапа нет.
- **Отчёт** — текст вида `report|plan|acceptance|guide|research|note`.
  У этапа или у задачи.
- **Файл** — всегда у задачи; этап и отчёт необязательны.
- **Событие** — append-only, `seq` по задаче.
- **Комментарий** — текст человека или роли.

## Состояния

```text
новая -> в работе -> ожидание / остановлена -> закрыта
                         ^                    |
                         └── возобновление <──┘
```

- Одна задача — один открытый этап.
- Нельзя закрыть задачу с открытым этапом.
- Возврат роли — новый круг, а не правка старого отчёта.
- Удаления задачи нет.

## Входы роли

Правило — данные проекта:

```json
{
  "from": "Планировщик",
  "kind": "plan",
  "round": "latest",
  "required": true
}
```

- `latest` — последний завершённый круг источника; нет отчёта — `input_missing`.
- `same` — тот же круг, который открывается.
- `previous` — предыдущий круг той же роли.
- `return` — отчёт, который вернул задачу. Возврат фиксируется при verdict
  `return`, `returned`, `возврат` или `на доработку`; событие `stage_returned`
  хранит `report_id`.
- Отката на более старый круг нет.
- `stage_start` отдаёт `role`, `round`, `kind`, `report_id`, `title`, `preview`.
  Полный текст — `report_get`.

## Отчёты

- В одном этапе одного вида — один отчёт.
- Отчётов задачи — сколько угодно, без этапа.
- Отчёт не редактируется.
- `stage_finish` создаёт главный отчёт этапа; `kind` по умолчанию `report`.
- `report_put` добавляет другой вид в открытый этап.
- `report_add` добавляет отчёт к задаче.

## Файлы

- `file_add` регистрирует путь, отдаёт `file_id` и `/files/<id>`.
- Путь не выходит за `root_path`.
- При сохранении отчёта ссылки `/files/<id>` проверяются и прикрепляются.
- Файл другой задачи — ошибка.

## Ошибки

`{code, message, hint, allowed}`.

| Код | Когда |
|---|---|
| `workspace_missing` | не передан проект |
| `workspace_unknown` | проекта нет; в `allowed` — доступные |
| `role_missing` | не передана роль |
| `role_unknown` | роли нет; в `allowed` — зарегистрированные |
| `task_missing` | не передана задача |
| `task_unknown` | задачи нет в проекте |
| `field_missing` | нет обязательного поля действия |
| `input_missing` | нет обязательного входа роли |
| `conflict` | открытый этап, дубль вида, занятость |
| `not_found` | нет отчёта, файла, события |
| `io` | ошибка диска или базы |

## Чего не делать

- Не подставлять «последнюю задачу».
- Не создавать роли и проекты на лету.
- Не проверять маршрут и порядок ролей в сервисе: это правила агентов.
- Не хранить картинки и код в базе.
- Не синхронизировать с GitLab.
