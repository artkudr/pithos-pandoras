# Архитектура кода

Зависимости идут внутрь. Внешний слой знает о внутреннем, внутренний о внешнем —
нет.

```text
cli ──> web ──┐
      └> mcp ─┴──> service ──> domain
                     │
                     └──> store ──> domain
```

## Слои

### `domain`

Типы, инварианты, ошибки, переходы состояний. Никакого I/O, `axum`, `rusqlite`,
`serde_json::Value` и файловой системы. Здесь живут `Project`, `Task`, `Stage`,
`Report`, `FileRecord`, `AppError`, правила вроде «один открытый этап».

Домен не знает, откуда пришли данные. Он проверяет то, что ему дали.

### `store`

SQLite: соединения, миграции, запросы, маппинг строк в типы домена. Здесь
`rusqlite`, `PRAGMA`, транзакции, FTS5. Writer — один; чтение — параллельно.

`store` не решает бизнес-правила. Если правило про «нельзя закрыть задачу с
открытым этапом», оно живёт в домене или сервисе, а не в SQL-строке.

### `service`

Сценарии: создать задачу, открыть этап, закрыть этап, добавить отчёт, собрать
входы роли. Оркестрирует `store` и `domain`, держит writer-очередь, проверяет
обязательные поля и права роли.

Один сценарий — одна публичная функция. Она принимает типизированные аргументы,
возвращает `Result<T, AppError>`.

### `mcp`

Транспорт для агентов: инструменты, схемы аргументов, разбор запроса, вызов
сервиса, сериализация ошибки. Никакой бизнес-логики.

### `web`

`axum`-роуты, `askama`-шаблоны, `rust-embed`, отдача файлов, SSE. Тонкие
обработчики: разобрать запрос, вызвать сервис, отдать ответ. Действия человека
пишутся с подписью `человек`.

### `cli`

`clap`, конфиг, запуск, миграции, `doctor`, `backup`. Здесь допустим `anyhow`.

## Куда добавлять

| Что | Куда |
|---|---|
| Новое правило домена | `domain`, тест рядом |
| Новый SQL-запрос | `store` |
| Новый сценарий | `service` |
| Новый инструмент MCP | `mcp`, вызов сервиса |
| Новая страница | `web`, вызов сервиса |
| Новая команда CLI | `cli` |

## Запрещено

- `axum` или `rusqlite` в `domain`.
- SQL в `mcp` или `web` в обход сервиса.
- Дублировать проверку обязательных полей в транспорте и сервисе по-разному.
- Тянуть `AppError` в HTML-шаблон без преобразования в человеческий текст.
- Делать «универсальный» слой `utils`, который знает обо всём.

## Ошибки на границах

- `domain` / `service` — `AppError`.
- `store` — `StoreError`, который преобразуется в `AppError` в сервисе.
- `mcp` — `AppError` в JSON `{code, message, hint, allowed}`.
- `web` — `AppError` в HTTP-статус и шаблон.
- `cli` — `anyhow` с контекстом.
