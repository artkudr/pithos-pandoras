# Rust: ядро

Пиши так, чтобы ошибка была видна в типе, а не в панике. Сначала границы и
инварианты, потом оптимизация.

## Ошибки

Домен и сервисы возвращают свой enum. `anyhow` — только на границе запуска.

```rust
#[derive(Debug, thiserror::Error)]
pub enum AppError {
    #[error("project не указан")]
    ProjectMissing,
    #[error("project `{0}` не найден")]
    ProjectUnknown(String),
    #[error("роль `{0}` не зарегистрирована")]
    RoleUnknown(String),
    #[error("io: {0}")]
    Io(#[from] std::io::Error),
}
```

Для ответа агенту ошибка разворачивается в `{code, message, hint, allowed}`.
`allowed` — список допустимых значений, если он есть. Не теряй его по пути.

Правила:

- `unwrap` / `expect` — только в тестах и при старте, где падение допустимо.
- Не глотай ошибку через `let _ = ...`.
- Не превращай все ошибки в строку: код ошибки — часть контракта.
- Для пользовательских данных — `Result`, не `panic!`.

## Async

`rusqlite` синхронный. В async-коде он допустим только так:

```rust
let rows = tokio::task::spawn_blocking(move || {
    let conn = Connection::open(path)?;
    load_tasks(&conn)
})
.await??;
```

Лучше — один writer-поток и пул чтения; подробности в `rust-data`.

- Не держи `Connection` или `Transaction` через `.await`.
- Не делай `std::thread::sleep` в async; используй `tokio::time::sleep`.
- Не блокируй runtime файловыми операциями на горячем пути: `spawn_blocking`.
- Отмену задачи проверяй естественно: не оставляй полузаписанных транзакций.

## Владение

- Принимай `&str`, `&[T]`, `&Path`; возвращай `String`, `Vec<T>`, `PathBuf`.
- `Clone` — когда действительно нужна копия, а не «чтобы компилятор успокоился».
- `Arc` — для состояния, которое разделяют задачи; `Mutex`/`RwLock` — только
  там, где нужен доступ из нескольких задач.
- Не прячь владение за `Box<dyn Trait>`, пока нет второй реализации.

## Имена и структура

- `snake_case` — функции, модули, переменные.
- `PascalCase` — типы, трейты, enum-варианты.
- `SCREAMING_SNAKE_CASE` — константы.
- Функция — глагол: `create_task`, `start_stage`, `finish_stage`.
- `try_` — для fallible; `is_` / `has_` — для bool.
- Один модуль — одна тема. Не делай `utils.rs` с разнородными функциями.
- Публичный API — маленький. Всё, что можно не публиковать, не публикуй.

## Зависимости

- Новая зависимость — с обоснованием в задаче или комментарии.
- Проверяй лицензию и размер. `cargo deny check`.
- Не добавляй крейт ради одной строки.
- Версии фиксируются в `Cargo.lock`; обновление — отдельным шагом.
