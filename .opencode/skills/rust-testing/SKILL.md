# Тесты

Тест доказывает поведение, а не повторяет реализацию.

## Уровни

| Уровень | Что проверяет | Где |
|---|---|---|
| Юнит | правила домена, разбор входов, ошибки | рядом с модулем |
| Интеграция | SQLite, транзакции, уникальные индексы | `tests/` |
| Конкурентность | два писателя, два этапа, номера | `tests/` |
| MCP | полный цикл через инструменты | `tests/` |
| Страница | рендер и отдача файлов | `tests/` |

## Временная база

```rust
use tempfile::TempDir;

fn test_db() -> (TempDir, Connection) {
    let dir = TempDir::new().unwrap();
    let path = dir.path().join("test.db");
    let conn = open(&path).unwrap();
    migrate(&conn).unwrap();
    (dir, conn)
}
```

- Каждый тест — своя база.
- Миграции применяются с нуля: тест проверяет и схему.
- Не используй общую базу между тестами и не полагайся на порядок.

## Обязательные сценарии

- Нет проекта, неизвестная роль, нет задачи — строгие ошибки с `allowed`.
- Исполнитель получает план планировщика последнего круга, а не первый и не оба.
- Пропал план последнего круга — `input_missing`, без отката.
- Одновременное создание задач — разные номера.
- Две задачи параллельно — обе идут, номера разные.
- Два `stage_start` одной ролью — тот же этап и `resumed: true`, без `conflict`.
- Две разные роли в одной задаче — вторая получает `conflict` с именем
  владельца.
- Два `report_add` к одной задаче — оба видны, конфликта нет.
- Отчёт в базе, файл по ссылке, картинка в нужном абзаце.
- Чужой файл в ссылке — ошибка.
- Переигровка событий и импорт старых задач — без расхождений.
- Полный цикл через MCP на чистой базе.

## Async-тесты

- `#[tokio::test]` для сервисов и MCP.
- Для блокирующих частей — `spawn_blocking`; не блокируй тестовый runtime.
- Не жди фиксированным `sleep`, если можно дождаться состояния.

## Имена

`test_<что>_<условие>`: `test_stage_start_second_returns_resumed`,
`test_task_create_parallel_numbers_are_unique`.

## Гейты перед сдачей

```text
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
tools/check.ps1
```

Провал любого гейта — не «готово». Если гейт пропущен, причина пишется в отчёт.
