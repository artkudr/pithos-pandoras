# Архитектура кода

Как разложить `src/`, чтобы правила домена не растворились в обработчиках.
Полная архитектура приложения — `docs/Сервис-задач-архитектура.md`.

## Слои

Пять слоёв. Зависимости идут внутрь: внешний слой знает о внутреннем, внутренний
о внешнем — нет.

```text
cli ──> web ──┐
      └> mcp ─┴──> service ──> domain
                     │
                     └──> store ──> domain
```

| Слой | Что делает | Чего не делает |
|---|---|---|
| `domain` | типы, инварианты, ошибки, переходы | не читает диск и базу, не знает про HTTP |
| `store` | SQLite, миграции, запросы, маппинг | не решает бизнес-правила |
| `service` | сценарии, writer, входы роли | не знает про `axum` и `rmcp` |
| `mcp` | инструменты для агентов | не содержит SQL и правил |
| `web` | страницы, шаблоны, файлы, SSE | не содержит бизнес-логики |
| `cli` | запуск, конфиг, `doctor`, `backup` | не дублирует сценарии |

## Карта `src/`

Текущая раскладка M1–M2:

```text
src/
  main.rs          — запуск
  lib.rs           — сборка приложения для тестов
  cli/
    mod.rs         — init, serve, doctor, import
    import.rs      — импорт старых задач
  domain/
    error.rs       — AppError и коды
    project.rs   — проект, роли, статусы
    task.rs        — задача, карточка, список, статистика
    stage.rs       — этап, круг, вход/финиш
    report.rs      — отчёт, превью, вход роли
    file.rs        — файл
    event.rs       — событие
    comment.rs     — комментарий
    input.rs       — правила входов из config_json
  store/
    db.rs          — соединение, PRAGMA, время
    migrations.rs  — версия схемы
    writer.rs      — один поток записи
    read.rs        — параллельное чтение
    projects.rs  — проекты, роли, статусы
    tasks.rs       — задачи, номера, статусы
    stages.rs      — этапы и круги
    reports.rs     — отчёты и входы
    files.rs       — файлы
    events.rs      — события
    comments.rs    — комментарии
  service/
    mod.rs         — сценарии
    inputs.rs      — сбор входов роли
  mcp/
    server.rs      — инструменты, HTTP-транспорт и проверка ключа
  web/
    mod.rs         — модуль страниц
    pages.rs       — доска, карточка, действия, файлы, проекты, поиск, статистика, настройки
    live.rs        — поток изменений для живой перерисовки
    templates/     — askama-шаблоны
    static/        — CSS и клиент живой перерисовки
  tray.rs          — окно в трее и запуск сервера
  bin/
    pithos-pandoras-tray.rs — GUI-бинарник трея
askama.toml        — каталог шаблонов
migrations/
  0001_init.sql    — схема M1
  0002_fts.sql     — FTS5-поиск
  0003_projects.sql — переименование workspace → project
  0004_file_comment.sql — комментарий к файлу
```

`web/` — чтение и действия человека. `/events` — позже.

## Правила границ

- `domain` не импортирует `axum`, `rusqlite`, `rmcp`, `askama`.
- `store` не возвращает `rusqlite::Error` наружу: только `StoreError`.
- `mcp` и `web` не вызывают `store` напрямую.
- Один сценарий — одна публичная функция сервиса.
- Ошибка приложения одна: `AppError` с `code`, `message`, `hint`, `allowed`.
- Действия человека идут с подписью `человек`; проверка ролей их не касается.

## Первый срез M1

В M1 нужны только эти части:

1. `domain` — типы и ошибки.
2. `store` — схема, writer, чтение, миграции.
3. `service` — создать задачу, открыть/закрыть этап, добавить отчёт, входы роли.
4. `mcp` — инструменты из таблицы архитектуры.
5. `cli` — запуск и миграции.

`web` появляется в M2. Не начинай с шаблонов и страниц.

<details>
<summary>Технические детали</summary>

- `rusqlite` синхронный: writer — отдельный поток или задача с одним соединением;
  чтение — пул или `spawn_blocking`.
- `tokio` — multi-thread runtime; блокирующие вызовы не держат runtime.
- `uuid` v7 для идентификаторов; `time` для RFC3339 UTC.
- `serde` — только на границах; в домене типизированные структуры, не `Value`.
- `askama` и `rust-embed` — в `web`, не раньше M2.
- `rmcp` — в `mcp`; сервер на `/mcp`, тот же порт `8787`.
- Миграции — `migrations/NNNN_*.sql`, только вперёд, версия в `schema_migrations`.

</details>
