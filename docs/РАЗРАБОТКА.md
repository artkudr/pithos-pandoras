# Разработка

Как собрать, проверить и не потерять контекст.

## Что нужно на машине

- Windows 10/11.
- PowerShell 7.
- Rust: `rustup` и Visual Studio Build Tools с рабочей нагрузкой
  «Разработка классических приложений на C++».
- `uv` — для локального индекса graphify.
- Git — для версий и автообновления индекса.

Проверить окружение:

```text
tools/setup-dev.ps1
```

Поставить graphify, если его нет:

```text
uv tool install graphifyy
```

## Первый запуск

Создать проект:

```text
cargo run -- init --project PithosPandoras --root . --db pithos-pandoras.db
```

Запустить сервер для агентов:

```text
cargo run -- serve --db pithos-pandoras.db
```

Адрес MCP: `http://127.0.0.1:8787/mcp`. Страница: `http://127.0.0.1:8787/`.
Проверка базы и открытых этапов:

```text
cargo run -- doctor --db pithos-pandoras.db
```

## Ключ доступа

`serve` читает `pithos-pandoras.key` или создаёт его при первом запуске.
Ключ печатается только при создании; потом его показывает `pithos-pandoras key`.
В stdout идёт только ключ, путь к файлу — в stderr. Если файла нет, команда
создаёт его. Клиент MCP передаёт заголовок `Authorization: Bearer <ключ>`.

- другой путь к файлу — `--key-file`;
- явный ключ — `--key`;
- ключ в git не класть, `*.key` уже в `.gitignore`.

- FTS5-поиск по названию, постановке, отчётам и комментариям.
- Ключ доступа MCP: `Authorization: Bearer <ключ>`.
- MCP-сервер на `/mcp`: 22 инструмента, включая `task_create`, `stage_start`,
  `stage_finish`, `report_add`, `report_put`, `report_get`, `file_add`.
- CLI: `init`, `serve`, `doctor`, `key`, `import`, `backup`.
- Страница M2: доска `/p/{project}`, карточка `/p/{project}/tasks/{number}`,
  файлы `/files/{id}`, статика `/static/{path}`.
- Действия человека M3: создать задачу, изменить, статус, комментарий,
  остановить, возобновить, закрыть, переоткрыть. Подпись `человек`, роль не

- Задача, созданная человеком, сразу получает папку. Для задачи агента папку
  создаёт агент; на карточке есть кнопка «Создать папку» и загрузка файла,
  которая создаёт папку при необходимости.
- Страницы `/p/{project}/search`, `/p/{project}/stats`, `/p/{project}/settings`.
- Проекты M4: `/projects` — список и создание; `/p/{project}/settings` — пути,
  роли, статусы и `config_json`.
- Импорт старых задач: `cargo run -- import --project <имя> --path <папка> --db <база>`.
- Трей Windows: иконка, открыть страницу, выход; автозапуск через
  `tools/install-tray.ps1`.
- Копия базы: `cargo run -- backup --db pithos-pandoras.db`.
- Живое обновление страницы: `/events` (опрос) и `static/live.js`.
- Таблицы — единый вид: `.table-wrap` + `table.board`, правила в
  `.opencode/rules/design.md`.
- Markdown отчётов с очисткой HTML: `pulldown-cmark` + `ammonia`.
- Время в базе — RFC3339 UTC; на странице — местное время без пояса.
- `doctor` проверяет схему, integrity, внешние ключи, открытые этапы,
  пропавшие файлы и занятость порта 8787.
- Интеграционные тесты: `tests/core_cycle.rs`, `tests/projects.rs`.

Возврат задачи фиксируется, если `stage_finish` получил verdict `return`,
`returned`, `возврат` или `на доработку`. Событие `stage_returned` хранит
`report_id`; правило входа `return` берёт этот отчёт.

Пока нет: сборок под Linux и macOS и автозапуска там же.

## Живое обновление

`/events` отдаёт номер последней правки базы. Сервер раз в секунду сверяет
версию (`PRAGMA data_version`) и увеличивает счётчик, когда кто-то записал:
человек со страницы или агент через MCP. Страница спрашивает счётчик раз в
1,5 секунды и перезагружается при изменении. Если в форме есть несохранённый
текст, перезагрузки нет — появляется полоска «На странице есть изменения» с
кнопкой «Обновить».

Долгое соединение (SSE) не используем: браузер держит на хост не больше шести
соединений, и открытый поток занимал одно из них — после нескольких переходов
страницы переставали грузиться.

Клиент — `src/web/static/live.js`, стили — `.live-notice` в `style.css`.

## Копия базы

```text
cargo run -- backup --db pithos-pandoras.db
```

Копия делается через `VACUUM INTO`: снимок согласован, сервер можно не
останавливать. Файл `pithos-pandoras-<дата>-<время>.db` кладётся в `backups`
рядом с базой; каталог меняется флагом `--out`. После записи копия проверяется
через `PRAGMA integrity_check`. Файлы задач в копию не входят — команда печатает
корневые папки проектов, их копируют отдельно.

## Проекты

`/projects` — список проектов и создание. `/p/{project}/settings` — пути,
роли, статусы и `config_json` проекта. Проект стоит в адресе страницы,
поэтому две вкладки могут смотреть разные проекты. MCP-инструменты
по-прежнему принимают проект в запросе.

При создании проекта корень и папка задач проверяются: два проекта не могут
указывать на одну папку, а шаблон папки обязан содержать `{number}`.

## Импорт

```text
cargo run -- import --project PithosPandoras --path old-tasks --db pithos-pandoras.db
```

Импорт читает `Состояние.json`, `Задача.md` и `Артефакты/**`. Текстовые
артефакты (`*.md`, `*.txt`) кладутся в отчёты, остальные — в файлы. Номер задачи
сохраняется, счётчик ставится на единицу больше. Повторный импорт пропускает
уже существующие номера. Этапы и события из старого журнала не переигрываются.

## Зависимости

Зависимости уже добавлены, версии зафиксированы в `Cargo.lock`. Набор:
`tokio`, `axum` с `multipart`, `rmcp` с HTTP-транспортом, `rusqlite` с
`bundled`, `askama`, `pulldown-cmark`, `ammonia`, `mime_guess`, `chrono`,
`serde`, `tracing`, `tracing-appender`, `uuid` v7, `time`, `clap`,
`rust-embed`, `tray-icon`, `winit`, `open`, `tokio-stream`, `thiserror`,
`anyhow`; для тестов — `tempfile`.

Если нужно повторить набор на чистом каркасе:

```text
tools/add-deps.ps1
```

Скрипт вызывает `cargo add` и включает для `rmcp` feature
`transport-streamable-http-server` — без него MCP-сервер не поднимется по HTTP.

## Проверки

```text
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
tools/check.ps1
```

`tools/check.ps1` делает всё сразу и добавляет `cargo deny check`, если
`cargo-deny` установлен.

Правило: изменение не считается готовым, пока не прошли форматирование,
clippy и тесты. Если проверка пропущена, причина пишется в отчёт.

## Индекс

Перед вопросом «кто это вызывает» или «что сломается» — граф через MCP
`graphify`:

```text
query_graph "как устроен writer"
get_node "AppError"
get_neighbors "create_task"
```

В терминале без OpenCode: `graphify query`, `graphify explain`,
`graphify affected`. После правок — `graphify update .`.

Подробности — `docs/ИНДЕКС.md`.

## Windows-сборка и трей

Собираем только под Windows.

```text
cargo build --release --bin pithos-pandoras-tray
.\target\release\pithos-pandoras-tray.exe
```

Консольного окна нет, лог — `pithos-pandoras.log`. Меню трея: открыть страницу,
выход. Настройки — переменные `PITHOS_DB`, `PITHOS_PROJECT`, `PITHOS_PORT`,
`PITHOS_KEY_FILE`.

Автозапуск при входе:

```text
tools/install-tray.ps1
```

Скрипт создаёт ярлык в Startup с рабочим каталогом проекта, чтобы база и ключ
нашлись.

## Упаковка

```text
tools/package.ps1
```

Скрипт собирает иконки, затем `cargo build --release --bins`, и кладёт в `dist/`
папку и zip `pithos-pandoras-<версия>-windows-x64.zip`. Внутри — оба exe,
`assets/icon.ico` для ярлыка, `tools/install-tray.ps1` и `ПРОЧТИ-МЕНЯ.md`
(копия `docs/УСТАНОВКА.md`). Версия читается из `Cargo.toml`.

`dist/` в git не попадает. Перед выпуском версию в `Cargo.toml` поднимают
вручную; `Cargo.lock` обновляется при сборке.

## Иконки

Знак приложения — графитовая плитка с монограммой «PIPA»: `assets/icon.svg`. Из него
собирается всё остальное:

```text
tools/icon.ps1
```

Скрипт пишет PNG от 16 до 512, `assets/icon.ico` для ярлыка и сырые RGBA для
трея, затем копирует favicon в `src/web/static/`. Сборщик —
`tools/iconbuild`, отдельный крейт на resvg; в сборку приложения не входит.

Трей берёт 16, 24 или 32 точки по масштабу экрана. Менять картинку — только
в `assets/icon.svg`, PNG руками не править.

## Где что лежит

- `src/` — код.
- `assets/` — иконки: исходный SVG и собранные PNG, ICO, RGBA.
- `docs/` — архитектура и runbook.
- `tools/` — скрипты.
- `.opencode/` — правила и скиллы для агентов.
- `home-dev-kit/` — справочный архив с рабочего компьютера. Не часть проекта,
  в индекс не попадает. Ничего оттуда не переносим.
